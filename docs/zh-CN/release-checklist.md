## 首次版本

完成以下检查后，建议首个标签采用 **0.1.0**。项目有单台实测配置及诊断能力，
但兼容、安全及硬件矩阵仍属实验阶段。不要把本地“phase4”称作已发布语义版本，
也不要补造旧版日期；真实标签建立前使用 Unreleased。

后续按 SemVer 管理已文档化 API/配置行为。1.0 前也须明确说明不兼容变化，
补丁版本不应悄悄改变已部署 RF 配置。远程 URL 及标签确定后，再增加真实比较和发布链接。

<!-- section: owner -->
## GitHub 公开前的所有者操作

1. 审阅完整 Diff 及公开 RF 样本。所有者已确认 MIT 行为
   **Copyright (c) 2026 pachi-qwq**，2026 是版权年份，不属于名字。
2. 创建或选择真实 GitHub 仓库，再提交初始版本并仅推送审查后的源码。
   审计开始时没有提交或远程。不要上传包含 build/private、缓存、原始日志或 .git 的工作区压缩包。
3. 启用 GitHub Private Vulnerability Reporting，并确定长期私密行为投诉渠道。
   政策没有虚构邮箱，也不声称相关设置已开启。
4. 等待真实 GitHub 工作流运行，确认 Ubuntu 构建、主机测试、链接及格式，
   再添加 CI 徽章或据此设置分支保护。

以上为所有者手动操作，本任务不授权修改远程设置或公开发布。

<!-- section: firmware -->
## 分发固件二进制前

- 对整理后的二进制重新执行真实启动、SPI 健康、登录/信任/重启及基本灯效检查。
  旧版已验证灯效，本次认证计时修复目前只有本地测试。
- 保留 Arduino/SDK 声明，按 LGPL 提供相应源码及重链接材料，核对预编译 SDK/无线库条款。
  完整二进制分发包尚未准备，源码 MIT 不表示整份固件仅 MIT。
- 记录准确 Git 版本、环境、依赖、二进制哈希及实际硬件。
- 明确定时、载波/功率/距离校准、其他设备及真实灯具状态尚未验证，
  不从 CI 成功推导兼容性。
