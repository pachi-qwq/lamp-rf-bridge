# 故障排查

[English](../en/troubleshooting.md) · [文档导航](index.md)

先保存第一次失败证据，再改参数；打开端口前关闭其他串口工具。
接触线路前断开 USB，不要同时修改多个无关项目。

<!-- section: usb -->
## USB 与烧录

| 现象 | 下一项检查 |
| --- | --- |
| 没有串口设备 | 换 USB 数据线，运行 PlatformIO device list |
| CH343 显示未知设备 | 核对硬件 ID，安装微雪提供的 CH343 驱动 |
| 端口占用 | 关闭占用端口的程序 |
| 烧录停在 Connecting | 按住 BOOT，按下再松开 EN，最后松开 BOOT 后重试 |
| 高速烧录偶发失败 | 原烧录命令增加 --upload-speed 115200 重试 |
| 串口乱码 | 使用 115200 baud、UTF-8；烧录速率是另一设置 |

<!-- section: spi -->
## SPI 与芯片身份

| 现象 | 下一项检查 |
| --- | --- |
| 等待 SO/CHIP_RDYn 超时 | 断电检查 CC1101 第 7 脚 SO/MISO 到 GPIO19 |
| 身份全 0x00 或全 0xFF | 保存读数，检查 3V3、共地及排针方向 |
| 未知 VERSION | 保留原字节，核查丝印和版本；不能以非零判断成功 |
| 动线后读取中断 | 更换可疑杜邦线，再重复十次连续 SPI 检测 |
| 网页显示射频不可用 | 先诊断供电、接线与已记总线/状态错误，再复位 |

实测芯片为 PARTNUM=0x00、VERSION=0x14。PARTNUM 为零合法，
但不能单独证明通信成功。原搭建中未用万用表测量模块实际电压。

## 网络、登录与启动

使用设备当前串口或路由器显示的地址，不复制原所有者 IP。
路由器允许互通时，手机 5 GHz 可以访问 2.4 GHz 网关；
访客隔离或 VPN 路由可能阻止访问。.local 名称可选，不能替代核对实际 IP。

登录失败时打开 /login，核对私密 USB 输出的随机访问密码。
错误密码或挑战过期提示保留在表单中。信任属于具体 Host 及浏览器环境，
清除站点数据或换地址可能需重新登录。不要公开 access 输出。
未配网时使用串口打印的热点，物理 `setup` 命令可重新打开。

早期 iOS 循环登录由固定服务器全局 Digest 挑战引起，已用独立签名挑战处理。
早期 5..6 秒启动延迟通过空闲 TCP 预连接复现，当前仅在竞争时等待 200ms 后让出入口。
深色启动图只改变背景。调整无关 Wi-Fi/RF 设置前，先对照准确版本及脱敏连接证据；
此修复后使用者反馈启动一秒以内。

## 采集与控制

采集超时仍会保存窗口。先确认在 ARMED 后操作了正确实体键，
再对比同键重复采样，之后才检查名义频率、OOK、带宽/速率、RSSI 门限及噪声。
载波标志不适合作为唯一依据。

溢出、预触发截断或歧义回调需要复核数据，不能补造缺失位；
不要因为前缀相似就发送候选数据。分析器的 protocol_confirmed=false 是有意保留的边界。

“已发送”但灯无反应时，检查距离、遮挡、正确配置及实际灯具表现，
不要自动重复重试电源切换。其他遥控器即使标注 433 MHz，也可能需要独立分析。
当前没有经过验证的灯具状态回读来校正图标示意。

<!-- section: evidence -->
## Issue 证据

提供固件环境/版本、板型/模块、接线是否变更、准确失败命令及实际输出。
分享前去除 SSID、IP、MAC、密码、Authorization、Cookie 及无关射频通信，
注明未执行检查。使用[缺陷表单](../../.github/ISSUE_TEMPLATE/bug_report.yml)，
漏洞则使用[私密安全报告](../../SECURITY.zh-CN.md)。
